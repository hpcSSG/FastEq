## 需要用户提供的材料

1. **目标仓库地址、分支名、上游基准分支/提交**：当前只有源码目录，没有原 Git 历史。若要向 FastEq 主分支提 PR，需要基于真实上游检出再迁入 CPU 改动。当前本地分支名暂定 `kunpeng-cpu`。
2. **提交作者姓名、邮箱及新增源码许可归属**：本机未配置 Git 作者，本次不伪造身份创建提交；新增源码的许可需作者/单位确认。原 FastEq MIT 声明已保留。
3. **服务器环境剩余信息**：历史软件版本已收到；cn19793 / 作业 1886300 的实机报告进一步确认了 2×304 核、每核 1 线程、32 个 NUMA 节点（16 个有 CPU、16 个无 CPU）、Linux 内核版本、默认 GCC 10.3.1 与指定 GCC/G++ 12.3.1。用户另已确认 CPU 为鲲鹏 920 系列、操作系统为麒麟，见 [环境资料](ENVIRONMENT.md)。这些项目不再待补。仍缺具体 CPU 子型号、麒麟版本号（可通过 `/etc/os-release` 补充）、物理内存安装规格、队列资源上限、当前 Python 包版本/导入路径和实际 JIT 使用的编译器/动态库。采集进程仅允许 16 个 CPU，还需在正式 worker 中确认绑定与调度授权。使用 `test/scripts/collect_environment.py` 采集部分信息。
4. **重构后验证结果**：目标服务器上的 pytest 输出、微基准输出，至少 float32/float64、单线程/多线程；原历史结果不能视为本次包的验证。
5. **MACE 模型兼容材料**：已知历史模型为 MACE-OFF23_small.model，MACE 0.3.13、float64；仍需模型具体哈希、可分发的最小样例或生成方法，以及原始/本分支版能量、力、应力误差。模型权重和数据集无需直接放进源码库。
6. **如果已有 cuEquivariance/MACE 补丁**：补丁代码和对应版本。原参考库的三个 third-party 子目录为空，无法据此恢复接口集成。

## 当前确实尚缺的功能（不是必须由用户自己实现）

- cuEquivariance `use_fasteq=True` 和 descriptor 到 CPU 元数据的适配。
- 与上游 GPU 后端共存的构建/运行时派发；当前 CPU 独立包不支持混装。
- 真正融合的 MPTP；目前提供的只是 uvu + scatter 组合接口。
- FCTP/Linear/STC/径向 MLP 的完整参数梯度及高阶梯度。
- 融合 STC 对任意 correlation、非标量输出的支持。
- 全面的边界条件、各种 irreps/路径布局、不同 MACE 版本回归。
- CI、完整依赖锁定、目标架构 wheel 发布流程。已补充历史版本约束 `test/constraints-kunpeng.txt`，但它不是完整锁文件。

以上应按首个 PR 的范围取舍，不要求一次实现所有功能。建议首个版本明确定位为“鲲鹏 CPU 推理及输入梯度算子”，不要宣称完全替代 GPU FastEq。
